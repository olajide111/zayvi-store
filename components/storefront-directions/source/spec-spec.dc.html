6 · SPEC SHEET · SPEC

Assets, motion and how it fits the theme system

Required assets

Product images. A clean product photo per model (3:2), with a plain or transparent background.
Datasheets. A PDF per model from the manufacturer. The page only links to what exists.
Spec data (essential). Every model needs rated values in the same fields, so the table and compare view line up. Missing values show 'see datasheet', never a guess.
Fonts. IBM Plex Sans and Plex Mono, open licence.

Motion behaviour

Compare tray. Slides up 24 px when two or more items are ticked.
Rows. Background highlight on hover, no movement.
Everything else. Instant. The feel is tool-like and quick.
Reduced motion. The tray appears without sliding.

Navigation and page composition

Header. Category tabs and a model or spec search, plus a quote list instead of a bag.
Home. A hero, a sizing helper and category tiles.
Collection. A spec filter sidebar and a sortable table with tick-to-compare.
Product. Key specs as chips, a full specification table and a datasheet link.
Quote list. Quantities, unit prices and a Request a quote option beside Checkout.

Fit with the existing theme system

Template family. Extends product-specification with the table view, compare view and quote list. Existing theme untouched.
Tokens. Dark surface, accent blue, mono font, table density.
Best for. Electronics, solar, tools and parts bought by specification, and wholesale or trade buyers.
Rules kept. Specs shown only where the seller supplies them; no invented ratings, certifications or stock. WCAG 2.2 AA, with ticks announced to screen readers.
Open points for the review. (1) The quote list needs a quote-request flow that does not exist yet. (2) Compare and filtering need structured spec fields per product. (3) Nothing is built or applied; it needs sign-off from the named owner first.
